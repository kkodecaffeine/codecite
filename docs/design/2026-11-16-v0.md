# codecite v0 설계

작성일: 2026-11-16 · 상태: 승인

## 한 줄 소개

정책 claim CSV 를 근거로 질문에 답하고, 답마다 출처를 붙이는 한국어 정책 에이전트다.

## 왜 만드나

정책은 기획서보다 코드에 먼저 반영되고, 기획서는 금방 낡는다. 그래서 "이 정책 어떻게 돼요?" 같은 질문은 결국 개발자에게 간다. codecite 는 코드와 운영에서 확인한 정책을 claim 한 줄씩 모아 두고, 그 claim 만 근거로 답한다. 근거가 없으면 지어내지 않고 "근거 부족"이라고 말한다.

## v0 에서 하는 것과 하지 않는 것

| v0 에 넣는다                                                  | 로드맵으로 미룬다                                |
| ------------------------------------------------------------- | ------------------------------------------------ |
| claim CSV 소스, 한국어 BM25, 메모리 벡터 색인(로컬 JSON 캐시) | 외부 벡터 저장소 어댑터                          |
| OpenAI·Ollama 답변과 임베딩                                   | 재정렬기, 피드백 순위                            |
| API 키 없이 BM25 와 결정적 답변만으로 도는 모드               | 코드 지식(AST 심볼, 저장소 간 관계, 엔티티 관계) |
| 동의어·불용어·질문 말투 낱말 설정 파일, 한국어 기본 사전      | 조사 루프(도구 호출로 근거를 더 찾는 모드)       |
| 라이브러리 API, CLI, `node:http` 서버                         | Slack·노션 연동, 다중 턴 대화                    |
| 가상 회사 "도토리 마켓" 샘플 데이터와 골든 질문 평가          | 뒷받침·예외·충돌 판정 라벨                       |

## 쓰는 법

### 라이브러리

```ts
import { createCodecite, csvPolicySource, openAiClient } from 'codecite';

const codecite = await createCodecite({
  source: csvPolicySource({ path: 'policies.csv' }),
  llm: openAiClient({ apiKey: process.env.OPENAI_API_KEY }),
});

const result = await codecite.ask('적립금은 언제 사라져요?');
// result.status: 'answered' | 'insufficient_evidence'
// result.answer: Slack 이나 웹에 바로 보여 줄 문장
// result.citations: 답에 쓰인 claim 목록(claimId, 문장, 출처)
```

`llm` 을 빼면 답변 모델 없이 검색된 claim 문장으로 결정적인 답을 만든다. `embedder` 를 빼면 BM25 만으로 검색한다.

### CLI

```bash
npx codecite index                 # CSV 를 읽어 색인을 만든다. 내용과 모델이 같으면 건너뛴다
npx codecite ask "환불은 며칠 걸려요?"
npx codecite eval                  # 골든 질문으로 근거가 답변 모델까지 가는지 잰다
npx codecite serve --port 3000     # POST /ask { "question": "..." }
```

CLI 는 현재 폴더의 `codecite.config.json` 을 읽는다.

## 데이터: claim CSV

한 행이 claim 하나다. 모르는 열은 무시한다.

| 열                                                    | 필수   | 뜻                                                                                                                                               |
| ----------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `policy_group`                                        | 예     | 정책 묶음. 같은 질문에 함께 답할 claim 끼리 같은 값을 쓴다(예: `points`)                                                                         |
| `feature_name`                                        | 예     | 사람이 읽는 기능 이름(예: `적립금 만료`)                                                                                                         |
| `claim_statement`                                     | 예     | 정책 한 문장. 답변의 재료다                                                                                                                      |
| `claim_facet`                                         | 아니요 | `outcome`, `eligibility`, `amount`, `duration`, `schedule`, `expiration`, `exception`, `reversal`, `procedure` 중 하나. 비우면 문장에서 추론한다 |
| `claim_id`                                            | 아니요 | 비우면 묶음·종류·문장의 해시로 만든다. 행이 움직여도 바뀌지 않는다                                                                               |
| `claim_confidence`                                    | 아니요 | `high` 또는 `low`. 기본 `high`                                                                                                                   |
| `claim_conditions`, `claim_exceptions`, `claim_value` | 아니요 | 조건·예외·값. 답변이 빠뜨리지 않게 지킨다                                                                                                        |
| `user_question_examples`, `search_aliases`            | 아니요 | 사람들이 실제로 묻는 말. 검색에 쓴다                                                                                                             |
| `context_text`                                        | 아니요 | claim 을 둘러싼 설명                                                                                                                             |
| `source`                                              | 아니요 | 출처(파일 경로, URL). 인용에 그대로 나간다                                                                                                       |

## 설정: `codecite.config.json`

```json
{
  "source": { "type": "csv", "path": "policies.csv" },
  "llm": { "provider": "openai", "model": "<답변 모델 이름>" },
  "embedding": { "provider": "openai", "model": "<임베딩 모델 이름>" },
  "index": { "path": ".codecite/index.json" },
  "vocabulary": {
    "synonyms": { "적립금": ["포인트", "리워드"] },
    "stopwords": ["알려줘", "궁금해요"],
    "groupAliases": { "points": ["적립금", "포인트"] }
  }
}
```

`vocabulary` 는 한국어 기본 사전(질문 말투 낱말 "뭐가", "있어", "주세요" 등)에 더해진다. 서비스마다 다른 말은 여기에만 둔다. 코드에는 특정 서비스의 용어를 넣지 않는다.

API 키는 설정 파일에 쓰지 않고 `OPENAI_API_KEY` 환경 변수로만 받는다.

모델 이름은 기본값을 두지 않는다. 모델은 자주 바뀌고, 어떤 모델을 쓸지는 쓰는 곳의 비용·품질 판단이기 때문이다. `llm`·`embedding` 의 `provider` 를 정했으면 `model` 도 적어야 하고, 비어 있으면 설정을 읽을 때 어느 항목을 채우라는 오류가 난다. 키가 없어 결정적 모드로 돌 때는 모델이 필요 없다.

## 파이프라인

1. **질문 다듬기**: 질문 말투 낱말을 걷어 내고 동의어를 펼친다.
2. **(선택) 질문 계획**: 답변 모델이 있으면 검색어와 원하는 claim 종류를 뽑는다. 실패하면 건너뛴다.
3. **검색**: BM25 와 dense 검색을 따로 돌려 RRF 로 합친다. dense 는 임베딩이 있을 때만 쓴다.
4. **정책 묶음 범위**: 질문 낱말을 가장 많이 덮는 묶음만 남긴다. 다른 묶음 claim 이 섞여 들지 않게 한다.
5. **anchor 근거**: 질문 핵심어와 직접 겹치는 claim 을 검색 순위와 무관하게 앞자리에 둔다.
6. **충분성 판정**: 근거가 질문에 답할 만한지 본다. 모자라면 답변 모델을 부르지 않고 "근거 부족"으로 끝낸다.
7. **근거 묶기**: 정해진 개수와 글자 수 안에서 claim 을 고른다. 조건·예외·값은 잘리지 않게 지킨다.
8. **답변 생성**: 묶은 근거만 보고 답한다. 근거 밖의 조건을 지어내지 않게 프롬프트 경계를 둔다.
9. **답변 검사**: 근거에 없는 조건을 지어냈거나 답을 피해 가면 결정적 답변으로 바꾼다.
10. **답변 계약**: 문장·항목 수를 맞추고, 근거에 있던 숫자 조건이 빠지면 되살린다.
11. **공개 정보 정제**: 내부 식별자, 파일 경로, 프롬프트 문구가 답에 새지 않게 걷어 낸다.

답변 모델이 실패하면 7 단계의 근거로 결정적인 답을 만든다.

### 결과 형태

```ts
interface CodeciteAnswer {
  status: 'answered' | 'insufficient_evidence';
  answer: string;
  citations: Array<{
    claimId: string;
    policyGroup: string;
    statement: string;
    source?: string;
  }>;
  /** 어떤 경로로 답했는지. 디버깅용 */
  trace: {
    retrieval: 'hybrid' | 'bm25';
    generation: 'llm' | 'deterministic';
    candidates: number;
    packed: number;
  };
}
```

## 모듈 구성

런타임 의존성은 0 이다. OpenAI·Ollama 는 `fetch` 로 부른다. ESM 으로 빌드하고 Node 22 이상을 지원한다.

```
src/
  domain/        claim, 정책, 조각(chunk) 모델
  text/          한국어 조사·띄어쓰기, 낱말 나누기, claim 종류 추론
  retrieval/     BM25, RRF, 묶음 범위, anchor, 충분성, 하이브리드 검색, 메모리 벡터 색인
  generation/    근거 직렬화, 근거 묶기, 프롬프트, 답변 검사, 답변 계약, 결정적 답변
  safety/        프롬프트 경계, 공개 정보 정제
  adapters/      CSV 소스, OpenAI, Ollama, JSON 색인 캐시
  config.ts      설정 읽기와 기본 사전
  codecite.ts    createCodecite: 위 단계를 엮는 허브
  cli.ts, server.ts, index.ts
```

포트(교체 가능한 경계)는 다섯 개다: `PolicySource`, `Embedder`, `LlmClient`, `VectorIndex`, `Logger`. 외부 저장소나 다른 모델은 이 포트를 구현해 붙인다. 답변 모델 어댑터는 모델을 부르는 일만 하고, 답변 검사·계약·정제는 모두 `generation/` 과 `safety/` 의 순수 함수가 맡는다.

모듈마다 단위 테스트를 둔다.

## 오류 처리

- **CSV 형식 오류**(필수 열 없음, 알 수 없는 facet): 행 번호와 함께 색인 단계에서 실패한다. 조용히 건너뛰지 않는다.
- **임베딩 실패**: 경고를 남기고 BM25 만으로 검색한다. `trace.retrieval` 이 `bm25` 가 된다.
- **질문 계획 실패**: 건너뛰고 질문 원문으로 검색한다.
- **답변 모델 실패·시간 초과**: 결정적 답변으로 바꾼다. `trace.generation` 이 `deterministic` 이 된다.
- **근거 부족**: 모델을 부르지 않고 `insufficient_evidence` 와 안내 문장을 돌려준다.

## 품질 게이트

- **단위 테스트**: vitest.
- **골든 평가**: `examples/dotori-market/golden-questions.json` 의 질문마다 기대 claim 이 답변 모델에 전달되는지(hitAny, hitAll) 잰다. 모델을 부르지 않는 오프라인 검사다. 기준선 파일보다 나빠지면 실패한다. 기준선은 사람이 PR 로만 바꾼다.
- **CI**: lint, typecheck, test, build, eval, gitleaks(비밀값 검사)를 PR 마다 돌린다.

## 데이터 원칙

- 실제 서비스의 데이터, 질문 원문, 정책 값, 계정·채널 id 는 넣지 않는다.
- 샘플 데이터와 테스트 예시는 가상 회사 "도토리 마켓"으로만 만든다.
- 문서와 주석은 한국어로 쓰고, 한글과 영어·숫자 사이는 한 칸 띄운다.

## 확장 계약(인터페이스)

로드맵 기능은 구현보다 계약을 먼저 연다. `src/extensions/` 에 기능마다 포트(interface)와 데이터 모양(type)만 두고, 구현은 쓰는 쪽이 붙인다. v0 허브는 이 계약을 부르지 않는다. 계약을 먼저 열어 두면 쓰는 쪽이 자기 저장소에서 구현을 먼저 만들어 볼 수 있고, codecite 가 그 기능을 넣을 때 같은 모양을 그대로 받는다.

| 파일                   | 계약                                                                                           | 무엇을 위한 것인가                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `code-knowledge.ts`    | 심볼 조회, 현재·과거 코드 색인, 시스템 토폴로지, 엔티티 관계, 필드 쓰기 색인, 코드 그래프 근거 | 정책을 문서가 아니라 코드에서 찾는다. 현재 코드와 변경 이력을 나눠 본다 |
| `research.ts`          | 조사 에이전트(턴 단위), 읽기 전용 조사 도구, 예산                                              | 근거가 모자랄 때 도구로 더 찾되 턴·호출·시간 예산으로 묶는다            |
| `reranker.ts`          | 재정렬기와 `off`·`shadow`·`on` 모드                                                            | 먼저 shadow 로 비교하고, 나아질 때만 켠다                               |
| `conversation.ts`      | 스레드 문맥, 대화 기억                                                                         | 이전 턴을 이어 받아 "그건요?" 같은 질문에 답한다                        |
| `feedback.ts`          | 답변 기록, 👍·👎 와 이유, 경험 사례                                                            | 틀린 답을 모아 다음 개선의 재료로 쓴다                                  |
| `observability.ts`     | 실행 관측, 런타임 캐시, 백업                                                                   | 답 하나가 어떤 근거로 나왔는지 끝까지 추적한다                          |
| `knowledge-refresh.ts` | 지식 갱신 트리거                                                                               | 기본 브랜치의 최신 코드로 지식을 다시 만든다                            |
| `catalog.ts`           | 목록 카탈로그, 공식 정책 문서                                                                  | "어떤 것들이 있나"에 일부가 아니라 전체 목록으로 답한다                 |

계약의 설계 원칙과 이 기능들이 왜 필요한지는 `docs/architecture.md` 에 쓴다.

## 로드맵

1. **코드 지식**: 저장소 목록에서 심볼·실행 사실·저장소 간 관계 그래프를 만드는 `codecite graph` 는 [그래프 설계](2026-11-16-graph.md)에서 먼저 만든다. 답변 엔진이 그 그래프를 코드 근거로 쓰는 일은 그 뒤에 한다
2. **v0.3 조사 루프**: 근거가 모자랄 때 읽기 전용 도구로 더 찾는 모드
3. **v0.4 연동**: Slack 봇, 노션 답변 기록, 외부 벡터 저장소 어댑터
4. **판정 라벨**: 근거가 질문을 뒷받침하는지, 예외인지, 서로 충돌하는지 가르기
