# codecite graph 설계

작성일: 2026-11-16 · 상태: 승인

## 한 줄 소개

저장소 목록을 주면, 각 저장소의 원격 기본 브랜치 고정 커밋에서 심볼과 실행 사실을 뽑고, 저장소 안팎의 호출·데이터 관계 그래프를 만든다. 결과는 [`src/extensions/code-knowledge.ts`](../../src/extensions/code-knowledge.ts) 계약 모양 그대로다.

## 왜 만드나

정책은 기획서보다 코드에 먼저 반영된다. 그런데 서비스가 여러 저장소로 나뉘면 저장소 하나만 봐서는 답할 수 없는 질문이 많다.

- 이 화면의 버튼은 어느 서버의 어느 처리기를 부르나
- 이 주문 상태 값을 다시 켜는 코드는 어느 저장소에 있나
- 이 큐에 넣은 메시지는 누가 꺼내 처리하나
- 이 테이블을 읽고 쓰는 서비스는 어디어디인가

사람은 저장소를 오가며 이 길을 따라간다. codecite graph 는 그 길을 미리 그려 둔다. 어느 회사에서든 저장소 목록과 몇 가지 힌트만 설정에 적으면 같은 그래프를 만들 수 있게, 회사·저장소·프레임워크에 묶인 규칙은 코드가 아니라 설정과 프리셋에 둔다.

## 하는 것과 미루는 것

| 이번에 넣는다                                                                         | 로드맵으로 미룬다                                          |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 저장소 목록 설정, 원격 기본 브랜치 고정 커밋 스냅샷, 바뀐 저장소만 다시 만들기        | 변경 이력(변경 이벤트 레코드)                              |
| TypeScript·JavaScript 추출기(선택 의존성 `typescript`), Python 추출기(`python3` 표준) | Swift·Kotlin·Java·Go 추출기(플러그인 인터페이스는 지금 둠) |
| 실행 사실(조건, 대입, 호출, 반환, 예외)을 레코드에 저장                               | 코드 임베딩과 외부 벡터 저장소                             |
| 프레임워크 프리셋 탐지기와 설정으로 더하는 탐지 규칙                                  | 답변 엔진이 그래프 근거를 쓰는 조회 구현과 조사 루프       |
| 저장소 간 연결, 엔티티 관계, 필드 쓰기 색인, 못 이은 항목 보고서                      | 외부 코드 색인 형식 입력 어댑터                            |
| CLI(`graph init/build/report/validate`), 라이브러리 API, 에이전트 스킬, README 안내   |                                                            |
| 도토리 마켓 다중 저장소 예제와 기대 연결 회귀 검사                                    |                                                            |

## 쓰는 법

### CLI

```bash
npx codecite graph init       # codecite.graph.json 뼈대를 만든다
npx codecite graph build      # 스냅샷 → 추출 → 탐지 → 연결 → 결과 파일
npx codecite graph report     # 못 이은 항목과 이유를 사람이 읽는 꼴로 보여 준다
npx codecite graph validate   # 결과 파일이 계약 모양과 규칙을 지키는지 검사한다
```

TypeScript·JavaScript 저장소를 읽으려면 `typescript` 를 함께 설치한다(`npm i -D typescript`). 없으면 그 저장소에서 멈추고 설치 방법을 알린다. Python 저장소는 `python3` 이 있어야 한다. 답변 엔진만 쓸 때는 둘 다 필요 없다.

### 라이브러리

```ts
import { buildCodeGraph, loadGraphConfig } from 'codecite/graph';

const config = await loadGraphConfig(process.cwd());
const result = await buildCodeGraph(config, { logger: consoleLogger });
// result.report.unresolved: 못 이은 항목과 이유
```

그래프 기능은 `codecite/graph` 진입점으로 따로 낸다. 답변 엔진만 불러오는 쪽은 `typescript` 를 읽지 않는다.

### 에이전트 스킬

[`skills/codecite-graph/SKILL.md`](../../skills/codecite-graph/SKILL.md) 는 AI 코딩 에이전트가 따라 하는 절차서다. 사람이 "이 저장소들로 그래프 만들어 줘"라고 하면 에이전트가 설정을 쓰고, build 를 돌리고, 보고서의 못 이은 항목을 코드에서 찾아 설정 힌트나 근거 있는 수동 연결로 채운 뒤 validate 로 마무리한다. 연결을 정하는 것은 결정적 엔진이고, 에이전트는 엔진이 못 잡은 빈칸을 근거와 함께 채우기만 한다.

## 설정: `codecite.graph.json`

```json
{
  "output": ".codecite/graph",
  "repositories": [
    {
      "name": "shop-api",
      "url": "https://github.com/dotori-market/shop-api.git",
      "defaultBranch": "main",
      "include": ["src/**"],
      "exclude": ["**/*.spec.ts"]
    },
    { "name": "shop-web", "path": "../shop-web" },
    {
      "name": "shop-worker",
      "path": "../shop-worker",
      "defaultBranch": "develop"
    }
  ],
  "presets": [
    "nestjs",
    "express",
    "fetch",
    "axios",
    "typeorm",
    "graphql-codegen",
    "python-requests"
  ],
  "hints": {
    "baseUrls": { "SHOP_API_URL": "shop-api" },
    "proxyPrefixes": { "/api/proxy": "shop-api" },
    "packages": { "@dotori/shared": "shop-api" },
    "graphqlSchemas": {
      "shop": { "repository": "shop-api", "paths": ["src/graphql"] }
    },
    "external": ["payments.example.com"]
  },
  "detectors": [
    { "kind": "queue-publisher", "call": "orderQueue.send", "nameArgument": 0 },
    { "kind": "queue-consumer", "decorator": "QueueHandler", "nameArgument": 0 }
  ],
  "entities": { "foreignKeySuffixes": ["Id", "_id"] },
  "groups": {
    "points": ["shop-api:src/points/**"],
    "refund": ["shop-api:src/refund/**"]
  },
  "manualLinks": "graph.links.json"
}
```

| 항목                   | 뜻                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `repositories`         | `url` 이나 `path` 가운데 하나. `defaultBranch` 를 비우면 원격 HEAD 를 따른다. 이름은 결과 파일 안에서 저장소를 부르는 이름이다 |
| `presets`              | 켤 프레임워크 탐지기 묶음. 아래 표                                                                                             |
| `hints.baseUrls`       | 클라이언트 코드의 주소 변수 이름 → 그 주소가 가리키는 저장소                                                                   |
| `hints.proxyPrefixes`  | 앞단 프록시 경로 접두어 → 실제로 받는 저장소. 접두어를 떼고 경로를 맞춘다                                                      |
| `hints.packages`       | 공유 패키지 이름(또는 범위) → 그 패키지를 내는 저장소                                                                          |
| `hints.graphqlSchemas` | GraphQL 스키마 이름 → 리졸버를 찾을 저장소와 경로                                                                              |
| `hints.external`       | 바깥 서비스 주소·이름. 이 문맥의 호출은 내부 처리기와 잇지 않는다                                                              |
| `detectors`            | 프리셋에 없는 자체 도구(큐 래퍼, 자체 데코레이터 등)를 탐지 규칙으로 더한다. 코드에 회사 규칙을 넣지 않기 위한 자리다          |
| `entities`             | 연결 컬럼 이름 규칙. 관계 선언이 없을 때 이름으로 추정하는 데 쓴다(추정 관계로 표시)                                           |
| `groups`               | 저장소·경로 → claim CSV 의 `policy_group`. 코드 근거와 정책 묶음을 잇는다. 비우면 묶음 없이 만든다                             |
| `manualLinks`          | 사람이나 에이전트가 근거와 함께 적은 연결. 결정적 연결과 따로 표시한다                                                         |

### 프리셋

| 프리셋                                        | 찾는 것                                                             |
| --------------------------------------------- | ------------------------------------------------------------------- |
| `nestjs`                                      | 라우트·컨트롤러 기본 경로, GraphQL 리졸버, 예약 작업, 이벤트 처리기 |
| `express`, `fastify`                          | 라우터 등록 경로                                                    |
| `nextjs`                                      | 파일 경로 라우트(`pages/api`, `app/**/route`)                       |
| `fastapi`, `flask`                            | 데코레이터 라우트                                                   |
| `fetch`, `axios`                              | TS/JS HTTP 호출                                                     |
| `python-requests`                             | `requests`·`httpx` 호출                                             |
| `graphql-codegen`, `apollo-client`            | 클라이언트 연산 → 연산 이름 → 루트 필드                             |
| `typeorm`, `prisma`, `mongoose`, `sqlalchemy` | 엔티티·컬럼·관계 선언, 갱신 호출(필드 쓰기)                         |
| `node-cron`, `celery`                         | 예약 작업                                                           |

프리셋은 `src/graph/presets/` 의 플러그인이다. 같은 인터페이스로 자체 프리셋을 만들어 설정에 경로로 넣을 수 있다.

## 파이프라인

```text
설정 검사
  → 스냅샷: 원격 기본 브랜치 끝 커밋을 묻고, 지난번과 같으면 그 저장소는 재사용
  → 파일 고르기: include/exclude + 바닥 규칙(.env*, *.env*, *.csv*, 비밀 경로, 바이너리, 테스트·예제·마이그레이션 기본 제외)
  → 추출(언어별 플러그인): 심볼, 관계, 실행 사실
  → 비밀값 가리기: 저장하는 원문과 실행 사실의 값
  → 탐지(프리셋 + 설정 규칙): 제공 쪽(라우트, 리졸버, 구독자)과 부르는 쪽(호출, 연산, 발행) 계약
  → 저장소 안 토폴로지
  → 저장소 간 연결
  → 엔티티 그래프, 필드 쓰기 색인
  → 보고서와 결과 파일
```

### 스냅샷

- 개발자 작업 트리는 읽지 않는다. `path` 로 준 저장소도 그 저장소의 원격 추적 브랜치 커밋을 임시 폴더에 따로 꺼내 읽는다. 원본 저장소에는 아무것도 쓰지 않는다.
- 저장소마다 읽은 커밋과 시각을 `manifest.json` 에 남긴다. 같은 커밋이면 같은 결과 파일이 바이트 단위로 같아야 한다.
- 지난번보다 심볼 수가 절반 아래로 줄면 그 저장소에서 멈춘다. 접근 권한이나 경로 설정이 잘못돼 그래프가 조용히 비는 일을 막는다.

### 추출기

```ts
interface SymbolExtractor {
  readonly name: string;
  readonly extensions: readonly string[];
  extract(
    files: readonly SourceFile[],
    context: ExtractContext,
  ): Promise<ExtractedSymbol[]>;
}
```

| 추출기       | 방식                                                                  | 필요한 것    |
| ------------ | --------------------------------------------------------------------- | ------------ |
| `typescript` | 컴파일러 API 의 구문 트리. `.ts .tsx .mts .cts .js .jsx .mjs .cjs`    | `typescript` |
| `python`     | `python3` 표준 `ast` 를 하위 프로세스로 한 번만 띄워 파일 묶음을 처리 | `python3`    |
| 사용자 정의  | 같은 인터페이스. 설정에 모듈 경로로 넣는다                            | 그 모듈      |

- 실행 사실은 레코드에 저장한다. 조건은 바깥 분기를 쌓아 두고(else 는 부정으로), 삼항식은 두 대입으로 나누고, 문자열 리터럴은 `<literal>`, 환경 변수 읽기는 `<env>` 로 바꾼다.
- `stableSymbolId` 는 저장소·파일 경로·심볼 이름의 해시다. 옮기거나 이름을 바꾸면 바뀐다. 옮김을 잇는 일은 변경 이력 단계의 몫이다.

### 탐지와 연결

[아키텍처 6.5](../architecture.md#65-확인한-관계와-추정한-관계를-나눈다)의 원칙을 그대로 따른다.

- 탐지는 구문 트리 위에서 한다. 주석이나 문자열 안에 같은 낱말이 있다고 탐지하지 않는다. 구문 트리가 없는 정규식 탐지는 문자열·주석을 같은 길이 공백으로 가린 뒤에 돈다.
- 호출 관계는 **후보가 정확히 하나일 때만** 잇는다. 둘 이상이면 잇지 않고 보고서에 "후보 여럿"과 후보 목록을 남긴다.
- 신뢰도는 탐지기마다 정한 값에서 시작해, 설정 힌트로 대상 저장소를 좁혔으면 `high`, 힌트 없이 모든 저장소에서 하나뿐이면 `medium` 이다.
- 같은 테이블이나 같은 캐시 키를 쓴다는 사실은 `SHARES_ENTITY`·`SHARES_CACHE_KEY` 간접 관계로만 둔다. 호출로 부르지 않는다.
- `hints.external` 문맥의 호출은 내부 처리기와 잇지 않는다. 바깥 API 경로가 우연히 내부 경로와 같아도 섞이지 않게 한다.
- 받는 쪽은 처리기에서 호출 관계를 따라 최대 세 단계까지 조건·예외 실행 사실을 모아 `handlerChain` 에 담는다.

| 관계                                       | 맞추는 방법                                                                                                                       |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `HTTP_CALLS`                               | 제공 쪽 라우트 표(기본 경로 + 경로, `:param` 정규화) × 부르는 쪽 호출의 메서드·경로. 주소 변수·프록시 힌트로 대상 저장소를 좁힌다 |
| `GRAPHQL_CALLS`                            | 클라이언트 연산 이름 → 연산 문서의 루트 필드 → 스키마 범위 안의 리졸버                                                            |
| `PUBLISHES_TO_QUEUE`·`CONSUMES_FROM_QUEUE` | 정규화한 큐 이름(설정 규칙의 이름 인자, 상수 값 따라가기)                                                                         |
| `PUBLISHES_EVENT`·`HANDLES_EVENT`          | 이벤트 이름. 같은 프로세스 안 이벤트는 저장소 안 관계로만 둔다                                                                    |
| `CRON_TRIGGERS`                            | 예약 작업 → 그 작업이 부르는 저장소 간 호출                                                                                       |
| `DEPENDS_ON_PACKAGE`                       | `hints.packages` 의 패키지를 가져오는 쪽 → 그 패키지를 내는 저장소의 심볼                                                         |
| `SHARES_ENTITY`·`SHARES_CACHE_KEY`         | 같은 테이블·같은 키를 읽고 쓰는 저장소. 테이블 이름과 엔티티 클래스 이름을 한 노드로 묶는다                                       |

### 엔티티와 필드 쓰기

- 엔티티 관계는 ORM 의 관계 선언에서 찾고(`declared`), 선언이 없으면 `entities.foreignKeySuffixes` 이름 규칙으로 추정한다(`naming`). 추정 관계는 답에서 단정하지 않는다.
- 필드 쓰기 색인의 키는 `저장소:필드` 이고, 항목마다 아는 경우 `entity` 를 단다. 대입, 쿼리 빌더 갱신, 갱신 호출, 문서 저장소 연산을 모은다. 키 하나의 항목 수는 모듈을 돌아가며 골라 자르고, 자르기 전 수를 남긴다.

## 결과 파일

```text
.codecite/graph/
  manifest.json            저장소별 커밋·시각, 설정 지문, 도구 판
  symbols/<저장소>.jsonl    CurrentSymbolRecord 한 줄에 하나(실행 사실 포함)
  topology.json            SystemTopologyGraph
  cross-repository.json    CrossRepositoryGraph(coverage 포함)
  entities.json            EntityRelationGraph
  field-writers.json       FieldWriterIndex
  report.json              못 이은 항목과 이유, 탐지기별 수
```

- 경로는 모두 저장소 기준 상대 경로다. 만든 컴퓨터의 절대 경로나 사용자 이름을 남기지 않는다.
- 심볼은 저장소마다 JSONL 로 나눠, 큰 저장소도 한 파일을 통째로 읽지 않게 한다.
- 정렬 순서를 고정해 같은 입력이면 같은 출력이 나온다.

## 보고서

연결을 못 한 것을 버리지 않는다. 그래프를 넓히는 일은 보고서를 읽는 데서 시작한다.

| 이유                 | 뜻                                                | 다음 할 일                                      |
| -------------------- | ------------------------------------------------- | ----------------------------------------------- |
| `no-provider`        | 부르는 쪽은 있는데 받는 라우트·리졸버를 못 찾음   | 대상 저장소 등록, 프리셋 켜기, 프록시 힌트      |
| `ambiguous-provider` | 받는 쪽 후보가 여럿                               | 주소 변수 힌트로 저장소 좁히기                  |
| `dynamic-target`     | 주소·큐 이름이 실행 중에 정해져 정적으로 못 읽음  | 수동 연결(근거 줄과 함께) 또는 그대로 둠        |
| `external`           | 바깥 서비스 호출                                  | 없음                                            |
| `no-caller`          | 받는 쪽은 있는데 부르는 쪽이 등록된 저장소에 없음 | 부르는 저장소 등록, 또는 바깥 클라이언트로 표시 |

`coverage.status` 는 기대 저장소가 모두 레코드를 가졌는지와 함께, 설정한 상한(`maxUnresolvedRatio`)을 넘는 못 이은 비율도 실패로 본다.

## 수동 연결: `graph.links.json`

```json
[
  {
    "relation": "HTTP_CALLS",
    "from": {
      "repository": "shop-web",
      "filePath": "src/order/cancel.ts",
      "symbol": "cancelOrder"
    },
    "to": {
      "repository": "shop-api",
      "filePath": "src/order/order.controller.ts",
      "symbol": "OrderController.cancel"
    },
    "evidence": "shop-web src/order/cancel.ts 의 주소는 런타임 설정에서 오지만 이 경로만 쓴다",
    "author": "agent"
  }
]
```

수동 연결은 `extraction.kind: "manual"` 과 근거 문장을 달고 결과에 들어간다. validate 는 양 끝 심볼이 실제로 있는지 확인하고, 없으면 실패한다.

## 에이전트 스킬 절차

1. 저장소 목록, 기본 브랜치, 읽기 권한을 확인한다. 원본 저장소는 읽기만 한다.
2. `graph init` 뒤 각 저장소의 의존성 파일(`package.json`, `requirements.txt` 등)을 보고 프리셋을 고른다.
3. `graph build` → `graph report`.
4. 못 이은 항목마다 코드를 읽고 이유를 정한다: 설정 힌트 추가, 탐지 규칙 추가, 근거 있는 수동 연결, 바깥 서비스 표시, 그대로 둠.
5. 다시 build → validate. 연결 수와 못 이은 수가 어떻게 바뀌었는지 보고한다.
6. (선택) 그래프와 코드를 읽고 claim CSV 초안을 쓴다. `source` 에 심볼 자리를, `claim_confidence` 는 `low` 로 두고 사람이 검토한 뒤 올린다.

지키는 것: 고정 커밋만 읽기, 비밀값을 옮겨 적지 않기, 추정 연결을 확인된 것처럼 쓰지 않기, 결과 파일을 손으로 고치지 않기(설정과 수동 연결로만 바꾼다).

## 오류 처리

| 상황                        | 동작                                              |
| --------------------------- | ------------------------------------------------- |
| 저장소에 접근 못 함         | 그 저장소 이름과 git 오류 요약을 보이고 멈춘다    |
| `typescript`·`python3` 없음 | 필요한 저장소와 설치 방법을 보이고 멈춘다         |
| 파일 하나의 구문 오류       | 그 파일을 건너뛰고 보고서에 남긴다                |
| 심볼 수 급감                | 그 저장소에서 멈춘다(지난 결과를 덮어쓰지 않는다) |
| 수동 연결의 끝 심볼이 없음  | validate 실패                                     |

## 품질

- 도토리 마켓 다중 저장소 예제(`examples/dotori-market/repos/`: API 서버, 웹, 작업자)를 저장소에 두고, 기대 연결 목록(`expected-links.json`)과 비교하는 회귀 검사를 CI 에서 돌린다. 기대 연결이 사라지거나 기대하지 않은 호출 연결이 생기면 실패한다.
- 같은 입력으로 두 번 돌려 결과가 바이트 단위로 같은지 본다.
- 결과 파일에 비밀값 모양과 절대 경로가 없는지 검사한다.

## 의존성

- 답변 엔진: 런타임 의존성 0 그대로.
- 그래프: `git` 명령, 선택 의존성 `typescript`(peerDependency, optional), 선택 실행 파일 `python3`. 그 밖의 런타임 의존성은 더하지 않는다.

## 계약 변경

- `CurrentSymbolRecord.policyGroup` 을 선택 필드로 바꾼다. `groups` 설정이 없으면 비운다.

- `CrossRepositoryExtractionKind` 에 `manual` 을 더한다.
